# DLT645-1997 API subset

`DLT645With1997` and `DLT645With1997OverTcp` implement the DLT645-1997
multi-function energy meter protocol.

`DLT645With1997` is the serial version. `DLT645With1997OverTcp` is the TCP
pass-through version. Both share the same data identification address rules.

Namespace:

```csharp
using HslCommunication.Instrument.DLT;
```

## Class and transport table

| Class | Base | Transport |
| --- | --- | --- |
| `DLT645With1997` | `DeviceSerialPort` | Serial |
| `DLT645With1997OverTcp` | `DeviceTcpNet` | TCP pass-through |

## Constructors

```csharp
new DLT645With1997()
new DLT645With1997(string station)

new DLT645With1997OverTcp()
new DLT645With1997OverTcp(string ipAddress, int port = 502, string station = "1")
```

`station` is a BCD meter address.

## Properties

```csharp
string Station
string Password
string OpCode
bool EnableCodeFE
bool CheckDataId
DLT645Type DLTType
IByteTransform ByteTransform
ILogNet LogNet
bool AutoReConnect
```

`DLTType` is `DLT645Type.DLT1997`.
`EnableCodeFE` adds the `FE FE FE FE` command header when enabled.
`CheckDataId` defaults to `true`.

For DLT645-1997, `Password` and `OpCode` are not used for write operations.

`ByteTransform` is `RegularByteTransform`.

## Connection

Serial:

```csharp
DLT645With1997 meter = new DLT645With1997("149100007290");
meter.SerialPortInni("COM3", 9600, 8, System.IO.Ports.StopBits.One, System.IO.Ports.Parity.None);
OperateResult open = meter.Open();
```

The Demo default serial parameters are `9600`, `8` data bits, no parity, and
`1` stop bit.

TCP:

```csharp
DLT645With1997OverTcp meter = new DLT645With1997OverTcp("192.168.1.10", 2000, "149100007290");
OperateResult connect = meter.ConnectServer();
```

The constructor default port is `502`. The Demo UI uses `2000`.

## Address rules

Addresses use the `DI1-DI0` format, for example `B6-11`.

The examples match the HslCommunicationDemo DLT645-1997 declarations.

| Address | Meaning | Read method |
| --- | --- | --- |
| `90-10` | Current forward active total energy | `ReadDouble` |
| `90-20` | Current reverse active total energy | `ReadDouble` |
| `91-10` | Current forward reactive total energy | `ReadDouble` |
| `91-20` | Current reverse reactive total energy | `ReadDouble` |
| `91-30` | Current first-quadrant reactive total energy | `ReadDouble` |
| `91-40` | Current fourth-quadrant reactive total energy | `ReadDouble` |
| `91-50` | Current second-quadrant reactive total energy | `ReadDouble` |
| `91-60` | Current third-quadrant reactive total energy | `ReadDouble` |
| `B2-10` | Last programming time | `ReadString` |
| `B2-12` | Programming count | `ReadInt32` |
| `B2-14` | Battery working time | `ReadInt32` |
| `B3-10` | Total phase-loss count | `ReadInt32` |
| `B3-20` | Accumulated phase-loss time | `ReadInt32` |
| `B6-11` | Phase A voltage | `ReadDouble` |
| `B6-12` | Phase B voltage | `ReadDouble` |
| `B6-13` | Phase C voltage | `ReadDouble` |
| `B6-21` | Phase A current | `ReadDouble` |
| `B6-22` | Phase B current | `ReadDouble` |
| `B6-23` | Phase C current | `ReadDouble` |
| `B6-30` | Total instantaneous active power | `ReadDouble` |
| `B6-40` | Total instantaneous reactive power | `ReadDouble` |
| `B6-50` | Total power factor | `ReadDouble` |
| `C0-32` | Meter number | `ReadString` |
| `C0-33` | User number | `ReadString` |
| `C0-34` | Equipment code | `ReadString` |

One-to-many mode can carry a station prefix:

```text
s=2;B6-11
```

## Read methods

```csharp
OperateResult<byte[]> Read(string address, ushort length)
OperateResult<int[]> ReadInt32(string address, ushort length)
OperateResult<double[]> ReadDouble(string address, ushort length)
OperateResult<string> ReadString(string address, ushort length, Encoding encoding)
OperateResult<string[]> ReadStringArray(string address)
```

`ReadDouble` is the main method for numeric meter values.

## Write methods

```csharp
OperateResult Write(string address, byte[] value)
OperateResult Write(string address, int[] values)
OperateResult Write(string address, double[] values)
```

## Meter control methods

```csharp
OperateResult ActiveDeveice()
OperateResult WriteAddress(string address)
OperateResult BroadcastTime(DateTime dateTime)
OperateResult ChangeBaudRate(string baudRate)
OperateResult Trip(DateTime validTime)
OperateResult Trip(string station, DateTime validTime)
OperateResult SwitchingOn(DateTime validTime)
OperateResult SwitchingOn(string station, DateTime validTime)
```

`ReadAddress()` is not supported for DLT645-1997.

`ChangeBaudRate` supports `600`, `1200`, `2400`, `4800`, `9600`, and `19200`.

## Async methods

`DLT645With1997OverTcp` provides full async read/write and meter control
methods.

`DLT645With1997` serial provides async versions for `ReadInt32`, `ReadDouble`,
`ReadString`, and the write overloads.

## Notes

- DLT645-1997 does not use generic PLC bool/word register methods such as
  `ReadBool`; use `ReadDouble`, `ReadInt32`, or `ReadString` with the DLT645
  data identifier.
- The low-level command-building and static helper methods are intentionally
  omitted from this reference.

## Creating this client inside HslCommunicationDemo (AI Gateway)

Verified end-to-end against a Demo `DLT645With1997Server`, with **both** a TCP page and a serial
page connected to the same server instance, and cross-checked in every direction: client write is
visible on the server, TCP write is readable from the serial page and the reverse, and a server
write is readable from a client.

Use **`double`** for this protocol, and the address form `B6-11` (block `B6`, item `11`).

### Address form

`B<block>-<item>` - verified working: `B6-11`, `B6-12`. Not valid on the working server: `B6-1`,
`B6-0`, `B6-10`, `B6-20`, `00-01-00-00`, `00-00-00-00`.

### Server side

```json
{"operation":"virtualServer.create","parameters":{"type":"DLT645With1997Server","tcpPort":2000,"startTcp":true}}
{"operation":"virtualServer.startSerial","parameters":{"serverId":"<serverId>","serialPort":"COM5-9600-8-N-1"}}
```

### Client A - TCP (`FormDLT645With1997OverTcp`)

```xml
<Device PipeSetting="TcpPipe" IP="127.0.0.1" Port="2000" ConnectTimeOut="5000" ReceiveTimeOut="10000" Station="1" Interval="1000" SleepTime="0" Type="FormDLT645With1997OverTcp" Name="DLT645访问Demo" Guid="49cce07bb0e3489fb437fb002eebea29">
  <AddressList>
    <Address Value="B6-11" />
  </AddressList>
</Device>
```

| Parameter | Value | Meaning |
| --- | --- | --- |
| `PipeSetting` | `TcpPipe` | Must be `TcpPipe` for the TCP page. |
| `IP` | `127.0.0.1` | Peer IP address. Also accepts `IpAddress`. |
| `Port` | `2000` | Peer TCP port. |
| `ConnectTimeOut` | `5000` | Connect timeout in ms. |
| `ReceiveTimeOut` | `10000` | Receive timeout in ms. |
| `Station` | `1` | Meter address. **`1` is what the working page uses** (note: unlike several other protocols, `0` is not the verified value here). |


### Client B - Serial (`FormDLT645With1997`)

```xml
<Device PipeSetting="SerialPipe" ComPort="COM6" BaudRate="9600" DataBit="8" StopBit="1" Parity="0" Station="1" Interval="1000" SleepTime="0" Type="FormDLT645With1997" Name="DLT645-1997访问Demo" Guid="6871db267dcf4f75953473122816b15e">
  <AddressList>
    <Address Value="B6-11" />
  </AddressList>
</Device>
```

| Parameter | Value | Meaning |
| --- | --- | --- |
| `PipeSetting` | `SerialPipe` | Must be `SerialPipe` for the serial page. |
| `ComPort` | `COM6` | Serial port name. `PortName` is accepted as an alias. |
| `BaudRate` | `9600` | Serial baud rate. |
| `DataBit` | `8` | Serial data bits. |
| `StopBit` | `1` | Serial stop bits. |
| `Parity` | `0` | Serial parity (0 = none). |
| `Station` | `1` | Meter address; `1` verified. |

### Verified read/write results (`B6-11`, `double`)

| Action | Result |
| --- | --- |
| TCP page writes `100` | TCP read `100.0`, server read `100.0` |
| TCP page writes `999` | TCP read `999.0`, server read `999.0` |
| Serial page writes `200` | serial read `200.0`, server read `200.0` |
| Serial page writes `888` | serial read `888.0`, server read `888.0` |
| TCP writes `777` | **serial** page reads `777.0` |
| Serial writes `888` | **TCP** page reads `888.0` |

Both client pages share one data pool, so a value written through either transport is visible
through the other.

### Two measured caveats

**1. Use whole numbers with this address.** Integer values round-trip exactly; a fractional value
comes back scaled. Measured on `B6-11` with `double`:

| Written by the TCP page | Read back |
| --- | --- |
| `0`, `1`, `10`, `25`, `100`, `999`, `1000` | identical (exact round-trip) |
| `12.3` | `1201.0` |
| `123.4` | `1200.0` |
| `12345` | `1234.0` |
| `-50.5` | `0.0` |

**2. `virtualServer.points.write` and the client page use different scaling for this address.**
This is the intended behaviour of this protocol, not a defect: the client page and the server-side API
express the same meter quantity through different value conventions, so on this address they differ by
a fixed factor of 10. Measured:

| `virtualServer.points.write` value | client page reads |
| --- | --- |
| `10` | `100.0` |
| `55.5` | `555.0` |
| `123.4` | `1234.0` |

To obtain a specific client-side reading from a server-side seed, divide by 10 - for example write
`55.5` so that the client page reads `555.0`. Always confirm with a client read rather than trusting
the write response, and prefer the client write path when you only need a round-trip test.
